# 01. 개요 및 목적

> 작성일: 2026-07-23 · 상태: 아키텍처·요구사항·UI 합의 완료, UI는 Pencil 목업(`document/design/page.pen`)으로 검증됨

## 무엇을 만드는가

DDD(도메인 주도 설계)의 **바운디드 컨텍스트와 도메인 명세를 시각적으로 편집하는 로컬 데스크톱 도구**.

- 명세는 워크스페이스의 YAML 파일(`context/*.yml`)로 저장되며, 파일이 **진실의 원천(source of truth)**
- 웹 UI(다이어그램)에서 생성·수정·삭제하면 즉시 로컬 YAML 파일에 반영 — IDE처럼 동작
- `biz-doc` 리포 자체가 이 도구의 프로젝트이며, `document/sample/context/swing-session.yml`은 개발·테스트용 샘플 명세

## 왜 만드는가

1. **Git 버전 관리**: 도메인 명세의 변경 이력을 코드처럼 diff/리뷰 가능하게 관리
2. **LLM 컨텍스트**: 사람과 LLM이 모두 읽기 좋은 YAML 명세를 유지해, LLM에게 도메인 지식을 전달하는 컨텍스트 자료로 활용
3. **시각적 설계 작업**: 관계(relationships) 중심의 DDD 명세를 Context Map 다이어그램으로 보면서 직접 편집

## 핵심 결정 요약

| 항목 | 결정 |
|---|---|
| 도구 형태 | 로컬 데스크톱 앱 (웹 서버 방식 아님) |
| 스택 | **React + Vite + TypeScript + Tauri** |
| 다이어그램 | React Flow (노드 드래그 배치, 드래그로 관계 연결) |
| 메인 화면 | 다이어그램 중심 (노드 클릭 → 상세 편집 패널) |
| 저장 방식 | 워크스페이스의 YAML 파일 직접 읽기/쓰기 |
| 파일 규칙 | **컨텍스트 1개 = 파일 1개** (`context/*.yml`) |
| 워크스페이스 | 폴더 선택 다이얼로그 + 최근 경로 기억 (VS Code 방식, 범용 도구) |
| 레이아웃 저장 | 명세 YAML과 분리 — 워크스페이스 루트 `.config/layout.json` |
| 설정 위치 | 뷰/도구 설정은 모두 워크스페이스 `.config/` 폴더에 구성 |
