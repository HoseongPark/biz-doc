# 04. 화면 구성 (UI)

> 상태: 구현 반영됨 (2026-07-25, `domains` 리스트 스키마 개정 기준) — Pencil 목업(`document/design/page.pen`)은 초기 설계안 기준이므로 세부는 본 문서가 우선

## 레이아웃

```
┌────────────────────────────────────────────────────┐
│ 상단 바: 로고 · 워크스페이스 경로 · 새로고침 · 컨텍스트 추가 │
├──────────╥─────────────────────────╥───────────────┤
│ 사이드바  ║      Context Map        ║  상세 패널     │
│ (240px,  ║      (React Flow)       ║  (300px,      │
│  조절가능) ║                         ║   조절가능)    │
│ 컨텍스트  ║  ┌─ 스윙 레코더 ──────┐  ║  유형 배지     │
│ /도메인   ║  │ 모델               │  ║  이름/설명     │
│ 트리     ║  │ [스윙 세션]        │  ║  속성/룰/관계  │
│ (모델/    ║  │ [스윙 레코더] …    │  ║  편집 폼      │
│  서비스   ║  ├───────────────────┤  ║  이력(하단)    │
│  그룹,    ║  │ 서비스             │  ║  삭제         │
│  접기)    ║  │ [스윙 점수 계산]    │  ║               │
│          ║  └───────────────────┘  ║               │
└──────────╨─────────────────────────╨───────────────┘
      (║ = 드래그로 패널 폭 조절하는 ResizeHandle)
```

- 사이드바 폭 160–480px, 상세 패널 폭 220–600px — 경계의 세로 핸들 드래그로 조절, localStorage에 유지

## 영역별 상세

### 상단 바
- 로고(biz-doc studio) · 워크스페이스 경로 pill · 폴더 열기 · 새로고침 · **컨텍스트 추가**(주 액션, accent 버튼)
- 컨텍스트 추가는 전용 다이얼로그(이름 + 파일명, `.yml` 검증, 오류는 다이얼로그 내 표시)

### Context Map (중앙, 메인 뷰)
- 컨텍스트 = 그룹 박스(accent 테두리, 제목은 컨텍스트 한글 이름)
  - 선택 시 **NodeResizer**로 박스 크기 조절 가능 (최소 480×520). 위치·크기는 `.config/layout.json`(`nodes`/`sizes`)에 저장
- **컨텍스트 박스는 두 구역으로 분리**:
  - **모델 구역(상단)**: "모델" 라벨 pill + AGGREGATE/ENTITY/VALUE/STEREO 카드들 (자유 배치)
  - **서비스 구역(하단 밴드, 200px)**: 연한 청록(`type-service` 저알파) 배경 밴드 + "서비스" 라벨 pill + SERVICE 카드들
- 도메인 = 박스 안의 카드. 카드 구성:
  - **테두리**: 유형 색상 — AGGREGATE(파랑, 1.5px) / ENTITY(초록) / VALUE(보라) / STEREO(주황) / SERVICE(청록)
  - **선택 하이라이트**: 탐색기/캔버스에서 선택된 도메인은 `.selected` 강조 (스토어 선택 상태 기준 — React Flow 자체 선택과 분리)
  - **유형 헤더 밴드**: 유형 소프트 색상 배경 + 유형 아이콘 + 유형 표시 라벨(Aggregate/Entity/Value/**Stereo**/Service). 아이콘은 사이드바와 동일 체계(database/component/diamond/list/workflow)
  - **AGGREGATE 강조**: 헤더 밴드를 솔리드 accent + 흰색 텍스트로 — 컨텍스트의 중심임을 표시
  - 제목: 한글 이름(`meta.name`)만 표시 (영문 도메인 키 없음 — 식별은 UUID `id`)
  - 속성 목록: 영문 속성명(모노스페이스) + 한글 설명(아래 줄) + 타입 칩(연회색 배지, 우측 정렬)
  - **비즈니스 로직 섹션**: `bg` 배경으로 속성 목록과 구분. 로직 이름(모노스페이스) + 설명
  - **STEREO 카드**: 속성/룰 대신 열거 값(values) 목록 — 유형 색상 도트 + 상수 이름(영문 대문자, 모노스페이스) + 한글 설명
  - **SERVICE 카드**: 속성 대신 오퍼레이션(operations) 목록 — 오퍼레이션 이름(모노스페이스) + 설명 + 관련 도메인 칩(`related-domains`는 UUID지만 칩에는 **도메인 한글 이름**으로 표시, 미해석 시 "(외부)")
- 코드 성격 텍스트(속성명·타입·로직명·오퍼레이션명·열거 상수)는 모노스페이스(JetBrains Mono), 한글 설명과 시각적으로 구분
- 관계 = 카드 간 화살표 + 관계명 레이블(예: `포함됨`)
  - 카드 4방향(상하좌우)에 연결 핸들 — 드래그로 다른 카드에 연결 → 관계명 다이얼로그 → 생성
- 노드 드래그 배치 → `.config/layout.json`에 좌표 저장
- 좌하단 줌 컨트롤

### 사이드바 (좌, 기본 240px)
- 컨텍스트 → 도메인 트리, 도메인 아이콘은 유형별 색상
- 컨텍스트 아래 도메인은 **"모델" / "서비스" 그룹 캡션**으로 분리 (그룹에 개수 뱃지)
- 컨텍스트·그룹 단위 **접기/펼치기** (셰브론 클릭, localStorage에 유지)
- 항목 클릭 시 선택 연동, 선택 항목은 accent-soft 하이라이트
- 파싱 오류 파일은 danger 색으로 표시

### 상세 패널 (우, 기본 300px, 선택 시 열림)
- **도메인 선택**: 유형 배지 · 이름 · 설명 → 속성 편집(또는 유형별 섹션) → 비즈니스 로직 편집 → 관계 목록(관계명 → 대상, + 관계 추가) → **이력(audit) 섹션은 패널 최하단**(작성자/생성/수정, 읽기 전용) → 삭제 버튼(danger)
  - 도메인 `id`(UUID)는 패널에 표시하지 않음 (앱 자동 관리 값)
  - **속성 편집은 속성 1개 = 카드 1장(묶음)**: 상단 한 줄에 속성명(모노스페이스)과 편집 아이콘, 가장 오른쪽에 타입 칩 — 속성명과 타입이 같은 레벨. 그 아래 줄에 한글 설명
  - **STEREO**: 열거 값 편집 / **SERVICE**: 오퍼레이션 편집 + `related-domains` 입력(쉼표 구분, 빈 값이면 키 제거)
  - 모든 입력은 blur 시 즉시 파일 저장 (값이 바뀐 경우에만 — audit 불필요 갱신 방지)
- **엣지(관계) 선택**: 관계명 수정 / 삭제
- **컨텍스트 선택**: 컨텍스트 이름 수정(blur 저장) / 도메인 추가(다이얼로그: 한글 이름 + 유형 select) / 삭제
- 추가류 입력은 모두 전용 다이얼로그 (window.prompt 미사용)

### 빈 상태
- 워크스페이스 미선택 시 "폴더 열기" 화면 + 최근 워크스페이스 목록 (Tauri appConfigDir의 recent.json)
